# Features of the W3C Open Source Program

W3C'sorganizational strengths provide meaningful opportunities for projects that
relate closely to W3C specifications, and support their development
and adoption.

* W3C is a trusted brand for neutral, multi-stakeholder governance.
* W3C has extensive experience convening communities to pursue Web-scale interoperability, through specification lifecycle management and policies that provide guarantees sought by multiple stakeholders.
* W3C specifications are developed within an IPR framework that facilitates their adoption by open source projects.
* W3C specifications increasingly define algorithms and code artifacts (e.g. WebIDL).
* W3C has a longstanding culture of open collaboration (CGs, WGs, MDN and Open Web Docs partnership) and open source development (tools, Web Platform Tests, validators), with a clear understanding of the open source ethos that lowers barriers to participation by open source practitioners.

## Core features

To start, we seek to provide these services to projects:

* **Governance**
  * Vendor-neutral governance that prevents single-vendor dominance and lends credibility to a variety of decisions both at the program level and within each project.
  * An IPR framework that aligns with the open source ethos, covers management of trademarks and copyright.
  * A baseline set of policies shared by all projects (e.g., code of conduct).
* **Resource management**
  * Institutional structure for sustained resources for the shared development and maintenance of projects (e.g., funding, people, hardware).
* **W3C branding**
  * W3C branding to enhance project visibility and standing.
* **Ecosystem connectivity**  
  * Proximity to W3C groups developing related specifications and staff-facilitated interactions and alignment.

## Advanced features

We hope to extend the program to support the following services:

* **W3C integration**
  * Structured support for contributions throughout the lifecycle of Web technology (OSS ↔ incubation ↔ standardization ↔ adoption), where W3C experience can help with lifecycle transitions.
  * Horizontal review opportunities (e.g., for projects with traction) to help ensure projects align with the larger W3C mission.
  * Infrastructure: CI, release processes, license compliance tooling, test framework.
* **Ecosystem connectivity**
  * Facilitated integration in web-scale projects, including browser codebases (e.g., through coding guidelines and dependency rules)
  * Improved mitigation of ecosystem risks via systematic reviews (including security), accelerated intervention programs in case of crises.
  * Safety programs to handle security vulnerabilities and provide accelerated intervention.
